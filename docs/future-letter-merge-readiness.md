## Совместимость с production

По сообщению пользователя уже установлены таблица, `submit_future_letter`, 014/015, секреты, функция, Vault и активный Cron с HTTP 200. **016 не применена.** Это принятый исходный статус, а не результат нового подключения к production.

Добавлен `tests/future-letter-production-compatibility.test.ts`: локальная БД моделирует именно состояние **014+015 без 016**. Проверено, что первый submit, сокращённый repeat, метаданные `deliver_on` и задержка 15 минут работают; благодарности сохраняют прежний прогресс. Frontend не зависит от наличия 016 и не обращается к старой RPC для task-16. Полная SQL-серия отдельно проверяет состояние после 016 и сохранение поведения благодарностей/Таро.

Остаётся проверить данные через **read-only** `docs/sql/future-letter-preflight.sql`: добавлены только обезличенные счётчики завершённых task-16 без строки в future_letters и ответов со старыми приватными полями. Такой старый результат реален для прежнего клиента: production submit отклоняет уже завершённое задание без письма. Автоматической конвертации/перезаписи данных не добавлено; обнаруженные случаи требуют отдельного решения оператора. Прогон тестов не доказывает, что таких строк в production нет.

Реальное успешное сохранение для smoke-теста не вызывалось: при активном Cron оно создаст настоящее письмо через 15 минут. Текущие определения production RPC, сетевые ответы реального endpoint и фактическая доставка заново не проверялись; совместимость подтверждена против предоставленных production-определений и описанного состояния.
