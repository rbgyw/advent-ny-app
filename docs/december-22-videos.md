# Видео на 22 декабря

## Подготовка Supabase

Один раз примените `supabase/migrations/006_advent_video_voting.sql` в SQL Editor своего проекта Supabase (либо через используемый процесс миграций). Она использует уже существующий RPC `save_task_progress`, который применяется остальными заданиями.

Создаются:

- `advent_video_catalog` — разрешённые ID роликов задания 22, их названия и порядок.
- `advent_video_votes` — один неизменяемый голос пользователя на каждый ролик: `liked: true` или `false`.
- `get_advent_video_state` — собственные оценки пользователя и общий рейтинг по количеству лайков всех пользователей.
- `vote_advent_video` — сохранение оценки и завершение задания после оценки всех опубликованных роликов.

Вызовы доступны только вошедшему пользователю после открытия назначенного задания. Чужие отдельные голоса клиенту не выдаются, прямое изменение таблиц закрыто. Повторные запросы, в том числе из другой вкладки, не накручивают лайки и не меняют первую оценку. Дизлайки не вычитают лайки.

## Добавление роликов

Заполните `public/collections/videos.json`. Пока там пустой массив, на экране отображается карточка-заглушка из макета; кнопки оценки отключены, голосование не запускается и выполнение задания не отмечается.

```json
[
  {
    "id": "video-01",
    "title": "Название ролика",
    "author": "Имя автора или команда",
    "description": "Короткое описание",
    "videoUrl": "videos/video-01.mp4",
    "posterUrl": "images/video-01.jpg"
  }
]
```

Обязательны `id`, `title` и `videoUrl`. Остальные поля можно пропустить. `id` — постоянный уникальный идентификатор из строчных латинских букв, цифр, `_` и `-`, до 64 символов. Не переиспользуйте ID удалённого ролика для нового: за ID закреплены голоса. Название — до 200 символов, в подборке — до 100 видео.

`videoUrl` должен вести непосредственно на видеофайл, например MP4 с H.264, доступный браузеру; ссылка на страницу YouTube или другого видеосервиса не является видеофайлом. Можно использовать полный HTTPS-адрес либо относительный путь от папки `collections/`. Для примера выше разместите файлы в `public/collections/videos/` и `public/collections/images/`.

После редактирования JSON выполните:

```sh
npm run video:catalog
```

Скрипт проверит поля и создаст `supabase/video-catalog.sql`. Выполните этот SQL в Supabase и опубликуйте обновлённый JSON с медиа. Список ID в JSON и активный каталог в БД должны совпадать. SQL не содержит самих видео, только ID, названия и порядок. Он добавляет или обновляет карточки, а удалённые из JSON помечает неактивными, сохраняя их историю голосов. Повторное выполнение SQL не сбрасывает оценки.

JSON и медиа в каталоге готового сайта можно заменить без пересборки приложения; серверный каталог после изменения списка ID тоже нужно обновить. Названия и порядок меняются тем же скриптом.

## Прогресс и рейтинг

Оценки и прогресс хранятся в Supabase. После повторного открытия приложение получает собственные голоса и пропускает уже оценённые карточки. Общий топ сортируется по числу лайков; равенство разрешается постоянным ID. Ролики без лайков не выдаются за лидеров. На итоговом экране показываются первые три места; рейтинг обновляется при возвращении во вкладку и берётся из Supabase.

После оценки последнего активного видео тот же серверный запрос сохраняет `{ "voted": true }` и завершение задания через `save_task_progress`. Если запрос не подтвердился, карточка остаётся доступной для повторной отправки; повтор уже сохранённого голоса безопасен.

Для повторного ручного теста на том же аккаунте нужно сбросить не только выполнение задания, но и его строки в `advent_video_votes`. Очистка браузера оценки не сбрасывает. Удаление тестовых голосов изменяет общий рейтинг.
